# Resume Tailor

A local web app for tailoring Justin Mendoza's three verified resume versions to a job description. DeepSeek (`deepseek-v4.1-flash`), accessed through Kyma, analyzes the posting; the app immediately shows structured, verified-data-only edits while the model automatically refines them. The server validates every operation against `data/verified_experience.json`, keeps substantive verified suggestions ahead of cosmetic reorders, shows a diff, applies only approved edits, and renders LaTeX into a PDF.

## Run locally

1. Use Node.js 20 or newer.
2. Copy `.env.example` to `.env` on first setup and enter your Kyma API key. The current model selection is DeepSeek through the existing Kyma adapter:

   ```dotenv
   KYMA_API_KEY=your_kyma_api_key
   KYMA_MODEL=deepseek-v4.1-flash
   KYMA_REFINE_TIMEOUT_MS=60000
   ```

   Keep `LLM_PROVIDER` unset or set it to `kyma`; DeepSeek is selected with `KYMA_MODEL`, not a separate provider adapter. `KYMA_BASE_URL` defaults to `https://kymaapi.com/v1` and can override the compatible API endpoint. If `KYMA_MODEL` is omitted or empty, the code still falls back to `qwen3.8-flash`. Refinement defaults to 60 seconds and is capped at 120 seconds. Restart `npm start` after changing `.env`, because the server loads configuration at startup.
3. Install a local TeX distribution that provides `latexmk` or `pdflatex`. The templates use the original Overleaf `fullpage` (TeX Live package `preprint`), `titlesec`, and `enumitem` packages, plus `hyperref`, `fancyhdr`, `babel`, `tabularx`, and Computer Modern fonts. On macOS, the app also checks `/Library/TeX/texbin`. For BasicTeX, install the additional packages in your user TeX folder (no admin password):

   ```sh
   /Library/TeX/texbin/tlmgr --usermode init-usertree
   /Library/TeX/texbin/tlmgr --usermode install preprint titlesec enumitem cm-super
   ```

   Run `init-usertree` only on first setup; skip it if the user tree already exists.
4. Run `npm start` and open `http://127.0.0.1:3001`. Set `PORT` if you need a different port.

No npm install is required. The server binds only to localhost. The Kyma key is read by the server and is never sent to the browser. The job description, resume-category names, and original verified bullet evidence go to the configured model for requirement analysis. Selected resume structure and relevant verified facts go to the configured model automatically for refinement after analysis; the app does not upload PDFs or contact details. Review controls unlock when refinement completes or times out, and verified local suggestions remain available either way. A retry button is available. Approved PDFs, LaTeX source, extracted text, and JSON coverage reports are saved in the ignored `output/pdf/` directory.

## PDF checks

The compiler runs with shell escape disabled. Text extraction uses Poppler (`pdftotext`) or macOS PDFKit; install Poppler on other platforms. Export fails if text extraction is unavailable or parsing checks fail. It validates contacts, section and bullet order, factual fields, displayed skill labels, and exact keywords. LaTeX overfull-box warnings block export. Text extraction cannot prove the absence of clipping or overlap: inspect the PDF preview before submitting. Compilation errors are shown in the UI. The app confirms the PDF exists and begins with a PDF signature. It checks page count with `pdfinfo`, or with macOS PDFKit when `pdfinfo` is unavailable; a multi-page result is rejected. If neither page-count method exists, export fails because one-page output cannot be verified.

## Extend the provider

`src/providers/index.js` defines the small provider boundary: `analyzeJD(input)`, `suggestEdits(input)`, `reviewEdits(input)`, and `connectionNote(input)` return JSON objects. `src/providers/kyma.js` is the current adapter and sends the configured model ID to Kyma’s chat-completions endpoint with JSON response mode. Its filename refers to the API provider, so it also handles the current DeepSeek selection. Runtime status shows the configured model ID; stage-specific failures distinguish generation, factual review, and validation. A future adapter can implement the same interface; the server-side validation and deterministic renderer stay unchanged.

Run `npm test` for local validation and rendering checks.

## Evidence-based requirement matching

The configured model returns canonical requirements, common aliases, category, priority, verbatim job-description source, and optional bullet IDs with exact evidence quotations. Source excerpts and technical terms are checked locally. Required technical skills rank above preferred qualifications; duplicate requirements and keyword frequency never add weight. Resume selection compares critical, high, medium, then low priority coverage; no ATS score is predicted.

The four dimensions are exact keyword presence, semantic requirement coverage, relevant experience evidence, and PDF parsing compatibility. Matching preserves tokens such as Go, C++, C#, and Node.js and multiword phrases. Curated aliases in the verified profile (such as AWS/Amazon Web Services and Kubernetes/K8s) support equivalent terminology. Model-suggested technical aliases cannot establish equivalence; unverified technical equivalences remain related. TypeScript and JavaScript are distinct requirements even when displayed together. Responsibilities require bullet evidence rather than a skill-list mention. Semantic responsibility assessments remain advisory: a real quoted bullet establishes provenance, not mathematical proof of equivalence. A resume declaration is identified separately from demonstrated bullet evidence.

New prose requires same-entry source bullet IDs, including the target bullet. Deterministic checks preserve original measurements and named technologies, reject invented numbers, restrict technology provenance and elevated ownership/deployment language, and reject hidden control text or LaTeX. A separate batch LLM audit then checks every factual clause, metric scope, potential versus realized outcomes, production claims, unsupported tools, and writing improvement. Only exact audited wording can reach approval; the server revalidates approved changes before compilation. This audit is a model judgment, not a factual guarantee. Unsupported valuable enhancements appear as confirmation questions and stay excluded until the verified profile is updated. Skill reorders preserve the full skill set. New skills must already exist in the verified profile. Strong bullets can remain unchanged; zero changes is valid. No model-generated prose is automatically treated as verified experience.

The UI shows requirement priority, match class, source, and evidence. Export includes `.tex`, `.pdf`, extracted `.txt`, and `.report.json` with exact/equivalent matches, missing and related requirements, priority coverage, existing versus introduced keywords, approved before/after edits, source evidence, factual review rationale, confirmation questions, and parsing results. Education, titles, employers, dates, and chronology remain fixed. No platform-specific scoring weights or assumptions are built in.

Design references: [Resume-Matcher's diff validation](https://github.com/srbhr/Resume-Matcher/blob/main/apps/backend/app/services/improver.py) informed the whitelist, original-value, and preservation safeguards; [ATS Screener](https://github.com/sunnypatell/ats-screener) informed the separation of keyword matching and parsing concerns. Neither application's UI, vendor simulations, nor scoring weights were copied.

Aggressive rewrite implementation: `src/rewrite-validation.js` contains deterministic gates, provenance binding, and batched audit orchestration; `src/matcher.js` contains narrow competency implications and priority-based matching. Curated implications include fault tolerance from outage buffering, asynchronous processing from producers/consumers, containerization from Docker, and stateful design from persistence plus deduplication. Related technologies never authorize equivalent skills. Skills can be added from the full verified profile, but a global skill declaration does not establish use in a specific project.

A typical run uses two model calls (requirements, edits) plus one batch audit when new prose is proposed. The audit has a 30-second timeout; analysis defaults to 90 seconds (`KYMA_ANALYZE_TIMEOUT_MS`, capped at 180 seconds) and edit timeout defaults to 60 seconds. Actual latency varies; 1–2 minutes is a goal, not a guarantee. Audit or refinement failure leaves the verified local fallback available. No new dependencies or services are required.

Export requires a verified single page, searchable text, intact content/reading order and no reported overfull boxes. Overflow rejects export; reject a lengthening edit rather than shrinking margins or fonts. Visual preview is still necessary to catch clipping/overlap that text extraction cannot establish. Tests use mocked model outputs for reproducibility; `npm test` also compiles all three templates and an approved rewrite when LaTeX plus Poppler or macOS PDFKit are available, otherwise that integration test explicitly skips. Live-provider wording quality and latency require evaluation against actual postings.

## ATS diagnostics

The analysis and final approved-resume report include weighted **demonstrated requirement coverage**: critical = 5, high = 4, medium = 2, low = 1. The percentage is demonstrated weight divided by total requirement weight (N/A for no requirements). Verified experience/project evidence, including narrow evidence-backed competencies, and qualifying education evidence earn credit; skills-only declarations and related-only assessments do not. This is a diagnostic, not an official ATS score or an optimization threshold. Existing priority-first base-resume selection remains unchanged.

The report distinguishes exact JD keywords, equivalent matches, critical requirements demonstrated or lacking demonstration, unsupported requirements, and presentation gaps. Presentation gaps include accurate JD wording that could be surfaced, skills declared without bullet evidence, and verified skills absent from the selected content. Technical requirements retain the JD's terminology when the model canonicalizes an equivalent alias. Existing before/after keyword lists still identify terms incorporated through approved edits.

`src/diagnostics.js` adds local repetition warnings and target-title terminology checks. Three or more mentions of the same technology (including curated aliases) within one bullet or skill group trigger an advisory review hint. This heuristic neither rejects export nor reduces coverage. Repeating a technology across Skills, project stacks, and substantive experience is allowed; the number of distinct technologies is unrestricted. Warnings need human judgment and may flag legitimate repetition.

Target-title diagnostics use the supplied job title and a small curated role vocabulary. They identify wording to review, never authorize unsupported experience, and never change previous official titles or seniority. Exact target-title presence is informational; absence is not a qualification failure. These diagnostics and presentation gaps appear in the existing final report display and downloaded JSON. PDF extraction continues using the existing contact, date, title, heading, skill, and reading-order validation; no additional PDF parser or model calls were introduced.

After successful resume generation, a LinkedIn connection note appears below the PDF preview with a **Copy connection note** button and character count. The PDF is available immediately; a separate request personalizes the note with the configured LLM using the full JD, role/company, and approved final experience bullets. The model selects a compact factual hook and returns supporting evidence IDs. Local checks enforce the 300-character maximum, cited evidence, supported technologies and numbers, followed by the existing independent factual audit. The generation call times out after 20 seconds and the audit after 30 seconds; any failure, invalid output or unsupported claim uses the complete deterministic fallback (`src/connection-note.js`). Repeated requests reuse the note promise for the current PDF. No draft is blindly truncated. The copy button unlocks when personalization finishes; stale results cannot replace a newer application's note. Clipboard errors leave the note available for manual copying. The app does not send LinkedIn invitations or messages.

Education prerequisites use structured degree, school, and date evidence in `src/matcher.js`, also supplied to JD analysis as `verifiedEducation`. BS/BSc/B.S./Bachelor terminology is recognized against the degree field, and alternatives such as BS/MS/PhD accept the matching level without inventing advanced degrees. Coursework does not count as an earned degree. Future graduation dates or explicit pursuing/expected status are shown as **Degree in progress** and related evidence when a completed degree is required; they receive credit only if the JD accepts pursuing/enrolled candidates. Additional GPA, accreditation, or graduation-deadline conditions remain flagged for verification. Education records appear in the existing requirement evidence and coverage report; the app reads its verified JSON data, not arbitrary PDF files supplied in conversation.

Broad competency matching also uses local, evidence-backed rules (`src/competencies.js`) when the model omits or underrates a match: provider ingestion demonstrates cloud/backend systems work, provisioning and deployment pipelines demonstrate infrastructure automation, VPC segmentation contributes to cloud architecture, and Datadog metrics demonstrate observability tooling. Specific tools, duration, production/multi-region scope, and bundled monitoring/alerting/logging capabilities remain separate conditions; generic evidence does not establish them. An example list such as “Datadog, Prometheus or OpenTelemetry” does not require all listed tools. Onsite/relocation/work-authorization constraints are shown as candidate confirmations and excluded from technical coverage, rather than treated as missing engineering experience.

Refinement diagnostics (`src/refinement.js`) preserve stage, error code, elapsed time and safe HTTP metadata. Provider timeouts, connectivity failures, API rejections, empty/truncated output, malformed JSON, and missing edit arrays are distinguished instead of all being reported as a generic unfinished request. JSON code fences are tolerated, but malformed/truncated content is not applied. If factual review fails, unaudited rewrites are withheld while other valid verified operations and existing suggestions remain reviewable. Server logs contain allowlisted metadata only, not API keys, provider response bodies, job descriptions or resume text.

Technology qualification parsing (`src/technical-requirements.js`) recognizes wrappers such as “Experience with Kubernetes” and simple AND/OR alternatives such as “Python and/or Go.” A supported alternative is sufficient for OR; AND requires all components. Unknown tools and additional scope remain unverified. The report uses existing bullet evidence and verified skill links, not literal full-sentence matching. Basic technology use is kept distinct from production expertise.

Aggressive rewrite validation rejects changes that only insert cloud/platform/infrastructure adjectives into otherwise unchanged text. Generation and review prompts prefer concrete implementation, engineering mechanisms, supported scope and outcomes, including combinations of complementary same-entry evidence. Already strong bullets can remain unchanged. Optional confirmation questions are displayed in a collapsed list separate from errors and approvable edits, and prompts avoid asking about already explicit facts or inventing stronger requirements than the JD.

Generation now evaluates bullets alongside their selected siblings. `src/entry-quality.js` withholds rewrites that newly repeat substantial accomplishment detail, and the existing batch audit checks semantic repetition using sibling context. Independent changes are also checked for conflicts with other proposed wording and curated alternatives, so approving a subset cannot rely on a companion rewrite to remove duplication. Shared technology names alone are allowed. The local overlap check is a heuristic; the model audit and final human review remain necessary for paraphrased duplication.

`src/relevance.js` ranks projects against all extracted requirements using selected verified evidence and named technologies, and ranks skills using requirement priority, including technologies named inside broader qualifications. Stable ties preserve the existing order. These rankings generate normal approvable diffs; they preserve skill breadth, employment chronology, titles and templates, and require no additional model calls.

Requirement matching recognizes candidate-confirmed employment durations (`verifiedDurationMonths`), preserving displayed dates and avoiding double-counting overlapping terms. Justin confirmed both May–August internships as four-month terms on October 15, 2026. The model receives these verified employment records; broad software engineering duration can satisfy a minimum, while specialized scope, excluded internships, future/invalid dates and unconfirmed durations cannot. The UI distinguishes verified months from duration still requiring confirmation.

The matcher splits the specific relational-databases AND transaction-safe-design conjunction, retaining independent evidence and gaps. PostgreSQL/MySQL project stacks establish relevant declarations, while demonstrated database operations and transaction guarantees require their own evidence. CI/CD improvements support developer-workflow requirements. In-person/onsite attendance is a preference/eligibility confirmation excluded from technical coverage regardless of the model’s category. A narrow extraction fallback recovers omitted explicit proficiency alternatives from the JD; Python/Django OR Go can be satisfied by verified Go without inventing Django.

On October 15, 2026, PostgreSQL evidence was supplemented by reviewing `hybrid-rag-search` revision `4113296e1c4ab11d42eb016e8687547c6889dbc2`: relational schema constraints, transactional atomic worker claims, lease-guarded checkpoints, and a transaction updating ingestion completion and document readiness. The verified `search_postgres` bullet records immutable source links. Infrastructure selects it instead of the local-load-test bullet; the original load-test evidence remains available, and General/AI retain their supplied selections. This supports relational database implementation and narrow transaction-safe design, without implying financial transactions, production deployment, or a particular isolation-level guarantee.

Ordering is generated deterministically for every analysis, including when the model returns no accepted edits. `src/relevance.js` ranks demonstrated critical requirements before supporting high/medium/low matches, counting each requirement once per item. It covers projects, bullets within each entry, project technology stacks, skills within categories and technical skill categories. Languages stays first and Spoken stays last; employment entries retain chronology. Stable ties keep the current order, repeated keywords earn no rank, and preference/eligibility and employment-duration records do not rank projects. Reorder proposals must put higher-ranked items first; irrelevant or regressive permutations are rejected. All orders appear as normal approval diffs, with no new model calls, dependencies, template changes, or keyword-density target.

The Kyma adapter sends DeepSeek’s native `thinking: { type: "disabled" }` option for DeepSeek model IDs; other models retain `enable_thinking: false`. JSON response mode and strict parsing remain enabled. HTTP failures expose only allowlisted provider codes, known parameter names and validated request IDs, never arbitrary provider messages (which may echo input). Refinement diagnostics retain safe provider codes/request IDs and preserve verified fallback suggestions. A 400 is not automatically retried unchanged or treated as proof of a context-length, credential or parameter problem; use its safe diagnostics to investigate the specific rejection.

Analysis timeout handling is independent of refinement: `KYMA_ANALYZE_TIMEOUT_MS` controls the initial JD call, defaults to 90,000 ms and caps at 180,000 ms. Invalid/nonpositive settings use the default. Duplicate original/current evidence text is omitted from the analysis payload when identical, and the prompt avoids redundant technology evidence in its output while retaining distinct requirements and semantic evidence. Timeout errors remain explicit; no fabricated analysis or unchanged automatic retry is substituted. Longer budgets allow slower gateway responses but do not guarantee success or a 1–2 minute total run.

After generation, “How this resume matches” displays the final approved resume’s weighted demonstrated requirement coverage, its percentage-point change from the base, critical requirements demonstrated, supported named JD keyword visibility and PDF text/reading-order verification. Expand strengths/gaps to see critical gaps, visible/missing verified keywords, other unproven requirements, presentation opportunities and preference/eligibility confirmations. This reuses the existing coverage report and local checks, makes no additional model calls, and adds nothing to the resume PDF. The percentage is not an ATS score or interview prediction; no score target, artificial rating bands or keyword quota is enforced. Keyword visibility recognizes verified aliases but is separate from proof of hands-on experience. No requirements yields N/A; unchanged or decreased coverage is reported honestly.
